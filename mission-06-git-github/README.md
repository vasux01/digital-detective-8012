# Mission 06 — Git and GitHub

## 1. Task / objective

The objective of this mission was to understand Git and GitHub, learn basic version-control concepts, work with branches and create a Pull Request.

## 2. Work completed

### Git terminology

| Term | Meaning |
|---|---|
| Git | A version-control system used to track changes in files |
| GitHub | An online platform for hosting Git repositories |
| Repository | A project folder whose changes are tracked by Git |
| Commit | A saved snapshot of changes |
| Branch | A separate line of development |
| Merge | Combining changes from different branches |
| Pull Request | A request to review and merge changes into another branch |
| Clone | Creating a local copy of a remote repository |
| Push | Uploading local commits to a remote repository |
| Pull | Fetching and integrating changes from a remote repository |

### Staging vs committing

Staging means selecting the changes that should be included in the next commit. Committing saves those selected changes as a snapshot in Git history.

### Branch activity

Created a separate branch named `update-about` to make changes without directly editing the main branch.

Added a section titled **My Learning** to the project README.

Pushed the branch to GitHub and prepared a Pull Request targeting the `main` branch.

## 3. Commands / tools used

| Command | Purpose |
|---|---|
| `git status` | Checks the current repository status |
| `git switch -c update-about` | Creates and switches to a new branch |
| `git add` | Stages selected changes |
| `git commit` | Saves staged changes |
| `git push` | Uploads commits to GitHub |
| GitHub | Hosts the repository and supports Pull Requests |

## 4. My understanding

Git helps track changes in a project and makes it easier to return to earlier versions. GitHub allows developers to store and share repositories online. Branches allow changes to be developed separately from the main branch. A Pull Request allows changes to be reviewed before they are merged.
